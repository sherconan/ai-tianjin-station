## 一、飞检通告

> 站长按：本档案为天津站 2026 年 4 月 24 日下午飞检产物。受检产品：Notion AI（已升级为 Notion 1.0 Agents 形态，2026 春季档）。
>
> 与昨晚 Manus 飞检的区别：Manus 是 **AI 原生**（你给一句话它跑全流程），Notion AI 是 **AI 增强**（在已有的工作区里就地召唤）。所以飞检的关键不是"它能不能干一件事"，而是"它有没有把工作区的上下文吃透"。

一句话定位：**「在你已经写了三年的工作区里，把 RAG 做成了交付品」**。

最终评级：**🟢 绿章 · 通过**。理由是站长跑了一个跨页 Q&A 的 case，**它诚实说出"找不到"而不是编造**——这件事在 RAG 产品里就是命门。再加上一个白送的彩蛋：Notion 把 AI Agents 的 token usage / cache hit rate / compaction 事件**全部对用户透明展示**，这是消费级 AI 产品里头一份。

## 三、实战测试 · 站长亲跑

### 3.1 飞检任务设计 · 三个角度

不同于 Manus 那种"扔一个总命令跑 4 步"的形态，Notion AI 是**嵌在工作区里的多入口**：
- 全局 `Ask AI`（侧边栏按钮 + ⌘O 新对话）
- 页面内 `/` 命令唤起 AI block
- 块级浮窗（选中文字后的 AI 改写/总结）
- AI 速记（会议自动转录 + 总结）
- AI 代理（自定义 workflow，新功能）

站长今天的飞检设计了三个角度：

| Case | 角度 | 入口 |
|---|---|---|
| 典型 | 跨页面 Q&A（RAG 真功夫） | 全局 Ask AI |
| 边缘 | 页面内总结（会议纪要 → 行动项） | 页面 AI 输入框 |
| 刁难 | 长文生成（PRD 大纲） | 全局 Chat |

**实跑结果**：典型 case 完整跑通并产出强证据；边缘 case 暴露了页面 AI 输入框的提交交互不一致问题（站长尝试 Enter / send 按钮均未稳定触发，反而是全局 Chat 的 Enter 一次就响应）；刁难 case 因为前一项 case 的 UX 摩擦未完整跑完——但**摩擦本身就是飞检素材**，站长把它写进锐评。

### 3.2 Case 典型 · 跨页面 Q&A 实录

**任务**：在站长本人 Notion 工作区里（22 个可见页面，包括 `Claude code 常用命令`、`NotebookLM 模板`、`local first 与云上记忆讨论`、`中金 部门间会议` 等），通过全局 `Ask AI` 入口提问：

```text
我之前在工作区里关于 AI 工具（Manus、Claude、ChatGPT）的核心 takeaway
有哪些？请引用具体页面。
```

**Notion AI 的回答（原话节选，未做任何修饰）：**

> 目前在你的工作区里，我能检索到的、明确与这三类工具相关且可归纳为"核心 takeaway"的内容主要集中在 **Claude**；关于 Manus 和 ChatGPT 的"核心 takeaway / 总结 / 心得"类笔记，**这次检索结果里没有找到足够明确的对应页面**（可能是没写在标题/正文里、用的是别的关键词、或在更私密/归档位置）。
>
> **Claude：核心 takeaway（已找到具体页面）**
>
> 1) 把 Claude Code 当成"命令行入口 + 可插拔 channel（插件/集成）"来用——你的记录重点在于：通过不同启动参数切换权限/通道、以及用 -resume / -p 等方式进入不同使用模式，说明你更偏向"把它当可脚本化工具链的一部分"。
>
> 2) 工作流 takeaway：**先读项目/知识库结构，再继续 ingest / query / lint**——你写了明确的操作顺序（读 SCHEMA.md、读 wiki/index.md、读 wiki/log.md 的最后 20 行，然后继续 ingest/query/lint）。
>
> 对应页面：**Claude code 常用命令**
>
> **Manus：未找到可引用的"核心 takeaway"页面**——本次工作区检索没有返回包含"Manus"且内容足够支撑总结/结论的页面结果（目前没有可引用来源）。
>
> **ChatGPT：未找到可引用的"核心 takeaway"页面**
>
> 如果你确定 Manus / ChatGPT 的笔记确实在工作区里，告诉我你当时更可能用的关键词（比如"Agent / workflow / 提示词 / 工具链 / 记忆 / RAG / 自动化 / 脚本 / 写作 / 会议纪要"等）或大概在哪个页面层级，我可以按你提供的线索把对应页面精确挖出来并补全 takeaway。

### 3.3 站长锐评 · 这一份回答的质量

**第一刀：找对了。**「Claude code 常用命令」页面真实存在且确实在站长侧边栏里，引用没编造。两条 takeaway 也跟那一页的实际笔记内容吻合（命令行入口、读项目结构再 ingest/query/lint）。

**第二刀：诚实承认未找到。** 这是站长今天最想看的一刀——RAG 产品最致命的失败模式是 hallucination。Notion AI 没编造一个"Manus 笔记"出来，而是明明白白说"没找到"，并补了三种可能解释（"没写在标题/正文""用的是别的关键词""在更私密/归档位置"）。**这个文案是产品经理写过的，不是模型自己的。**

**第三刀：主动 ask back。** 末段直接给出"如果你确定…告诉我关键词"——这是 IR 系统最佳实践，**把检索失败转成对话延续**，让用户能补充语义提示。Manus 类 agent 也常做不到这一点。

**第四刀：耗时 ~12 秒。** 从点 Ask AI → 提问 → 完整回答展示，挂壁时钟约 12 秒。这中间它至少做了：sidebar 展开 → 输入 → 检索 → 推理 → 流式输出。可接受。

### 3.4 边缘 Case · 页面内总结的 UX 摩擦实录

**预期路径**：在新建 page 里粘一段 200 字会议纪要，按 `/` 唤起 slash 菜单，选「总结 / Summarize」，Notion AI 直接产出 3 句结论 + 行动项 list。

**实际发生**：
1. 创建新 page → ✓
2. 通过页面底部的"使用 AI 处理各种任务..."输入框注入 prompt → 文字进入了 ✓
3. 按 Enter 提交 → ❌ 无响应
4. 找到右侧 32×32 的圆形 send 按钮（SVG 路径以 `M9.38 13.619` 开头，是箭头形状）→ click → ❌ 也无响应

**站长解读**：页面级的 AI 输入框跟全局 Chat 的 AI 输入框**虽然长得几乎一样，但提交契约不同**——全局 Chat 的 Enter 一次就响应（Case 典型已验证），页面级的可能要求 Cmd+Enter，或者 click 必须满足某种焦点状态。**对自动化测试来说这是地狱，对真实用户来说这只是"今天怎么按了没反应"的轻微挫败。**

但站长要把这条记下来：**Notion AI 的多入口设计是优点，但提交交互的不一致是它今天最明显的硬伤。**

### 3.5 站长意外发现 · AI Agents 的 token transparency

这是今天飞检最大的意外收获。

**事实**：当 Notion AI 在执行 Q&A 任务时，**右侧栏会展示一个对终端用户开放的"AI Agent 内部状态面板"**，包括：

```
Default model
Token Usage:
  34,142 / 272,000 (13%)
  Uncached Read:   1,416
  Cached Read:    32,128
  Output:            598
Next create:  50%
Next compact: 90%
Transcript tokens over time
  34,142 tokens · 13%
Step token count (relative height)
Summary created
Compaction activated

Cache hit rate by inference
  5 calls · 92% cached
  #1  91%  26,438 tokens
  #2  86%  30,128 tokens
  #3  95%  30,574 tokens
  #4  92%  32,726 tokens
  #5  96%  33,544 tokens
  Cached read · Uncached · Cache write
```

**站长打分：⭐⭐⭐⭐⭐（满分）。** 这一栏在 2026 年 4 月之前的 Notion AI 里**完全不存在**。它意味着 Notion 把曾经只有 Anthropic / OpenAI **API 开发者**才能看到的"prompt cache 命中率""context window 使用率""compaction 事件"——**直接搬到了普通用户面前**。

**为什么这件事重要：**
1. **AI 透明度是 2026 年的产品差异化**——绝大多数消费级 AI 产品要么把 token 当黑盒（用户不懂），要么干脆不显示（用户不焦虑）。Notion 选了第三条路：**显示，但用图形化呈现，让普通用户也能看懂**。
2. **它把"AI 用了多少钱"这件事交还给用户**。免费用户看到 13%，会知道还能跑多久；Pro 用户看到 92% cached，会知道为什么这次便宜。
3. **它对 Agent 类产品有教科书级示范意义**：所有正在做 Agent 的团队都该学这一栏。

> 站长锐评：**这一栏是今天飞检 Notion AI 拿绿章的决定性因素。** 它说明这家产品团队不是在"把 LLM 包一层 UI"，而是真的理解 LLM 内部机制并把它产品化。

## 四、核心 AI 能力拆解

通过本次实测，站长把 Notion AI 拆成 6 层：

### 4.1 跨页面 RAG 检索 ⭐⭐⭐⭐⭐
本次 case 的主角。能从 22 个页面里精准定位「Claude code 常用命令」并提炼 takeaway，且对未找到的内容明确说明，不编造。

### 4.2 多入口 AI 触发 ⭐⭐⭐⭐
- 全局 Ask AI（⌘O / 侧边栏按钮）
- 页面 AI 输入框（"使用 AI 处理各种任务..."）
- 块级 / 命令
- 选中浮窗
- 速记（meeting transcription）
- 代理（自定义 workflow）

**短板**：不同入口的提交契约不一致（已记入 3.4）。

### 4.3 AI Agents 透明度 ⭐⭐⭐⭐⭐
独家亮点。详见 3.5。

### 4.4 中文体验 ⭐⭐⭐⭐
本次 case 的 prompt 和回答都是中文。Notion 的中文化做得到位：sidebar 标签、按钮文案、AI 自我介绍（"思考完毕"）都是母语级。

### 4.5 上下文连贯 ⭐⭐⭐
对话被自动命名为"AI 工具核心要点总结"——这种自动 title 生成跟 Manus 同一档次。但站长注意到：**对话被自动保存到侧边栏「最近」区**，长期会污染列表，需要定期手动归档。

### 4.6 AI 速记 / Agents（未实测） ⭐⭐⭐
今天没跑通这两项（涉及日历 + 通话集成）。下次飞检留坑。

**对比 Manus**：Manus 是 AI 原生，所有功能都是 AI；Notion 是 AI 增强，AI 是给老产品加的辣椒。Notion 的盈利底子稳，AI 只是续命剂；Manus 的盈利底子全靠 AI，没有 AI 就没有产品。

## 七、站长锐评

### 让站长想盖绿章的：
1. **Q&A 不编造**——找到就找到，没找到就明说，并解释三种可能。
2. **AI Agents 的 token transparency 是行业首创级别**——对终端用户暴露 cache hit rate / compaction，**这件事其他消费级 AI 产品都没做过**。
3. **多入口设计**让 AI 嵌进了真实写作流程，不是新开一个聊天窗口让你"上来问"。
4. **诚实的 ask back**：「如果你确定笔记在工作区里，告诉我关键词」——把失败转成对话延续。
5. **对话自动标题**——和 Manus 同一档次，省心。

### 让站长摇头的：
1. **页面 AI 输入框的提交契约不稳定**——Enter 不响应，send button click 也没动静；只有全局 Chat 的 Enter 一次过。这是 UX 一致性的硬伤。
2. **Desktop app 弹窗反复打扰**——不主动安装就反复弹"在 Notion 桌面应用中打开"，有点强买强卖。
3. **对话自动保存到「最近」区**——长期会污染 sidebar，需要手动归档。
4. **AI 加购定价偏高**——免费用户的试用 quota 很紧，刚跑完 Q&A 就接近"再试就要升级"的边缘。

### 站长想问 Notion 团队的三个问题：
1. 页面级 AI 输入框能不能跟全局 Chat 输入框统一提交契约？现在是用户的盲区。
2. token usage 面板这么棒，能不能做成可贴到任何 page 的 widget？让用户能在自己的 dashboard 看自己的 AI 月度消耗？
3. AI Agents 测试版的"Default model"显示了 model 名，能不能让付费用户切换 Sonnet vs Opus？现在是黑盒。

## 八、飞检结论

### 评级：**🟢 绿章 · 通过**

| 项 | 评分 | 说明 |
|---|---|---|
| 任务理解 | A | prompt 一次性吃透 |
| 检索质量 | A | 对的页面对的内容 |
| 不编造 | A+ | RAG 命门守住了 |
| 中文表达 | A | 母语级 |
| 透明度 | A++ | Token panel 满分意外收获 |
| 多入口 | A- | 入口多但契约不一致 |
| 商业化 | B+ | AI 加购定价偏紧 |
| 容错恢复 | A | 失败时主动 ask back |

**综合：** Notion AI 已经过了"把 LLM 嵌进老产品"的关，**站长今天给绿章不是因为模型多强，而是因为产品团队对 LLM 内部机制的理解和呈现做到了消费级产品的天花板**。

### 给我们（产品人）的启示：

1. **「不编造」必须做到指令级别。** Notion AI 的 Q&A 在没找到内容时的回复文案——三种可能解释 + ask back 关键词建议——是被产品经理打磨过的 system prompt 的产物，不是模型自带的。**RAG 产品的护城河在 system prompt 而不是模型。**

2. **「token transparency」是 Agent 类产品 2026 年的新护城河。** 把 cache hit rate、compaction 事件、token usage 摆在用户面前，**用户会觉得你"诚实"和"专业"**，并产生独特的产品好感。所有正在做 Agent 的团队都该考虑这件事。

3. **「多入口 AI」要统一提交契约。** Notion 这次的硬伤就在这——同一个 placeholder 长得一样，但页面里按 Enter 没用，要去全局 Chat 才有用。**入口可以多，交互必须统一。**

4. **「AI 加购模式」对 ARPU 是双刃剑。** GitHub Copilot 和 Notion AI 都用这套，但它本质上是把"愿意为 AI 付费的用户"和"不愿意"分开收钱。如果产品的 AI 价值还没大到让大多数用户必买，加购模式会比"全员涨价"更稳，但也更慢。

5. **「对话自动归档」必须做。** Notion 现在让对话自动落到 sidebar「最近」是反例——长期会污染。Claude.ai / ChatGPT 的"自动归档到 chat history 但不挂在主导航"才是正解。

## 附 · 三脆弱点自检（站长本人）

> 飞检完了，站长也得自检一下今天这份档案的三个脆弱点：

1. **Case 典型 ✅ + 边缘 ⚠️ + 刁难 ❌**——只有第一个 case 完整跑通。边缘和刁难因为页面 AI 输入框的 UX 摩擦没拿到完整证据。补救是**把摩擦本身写进锐评**，但下次飞检 Notion 应该提前 wireframe 好"如果某个 case 不通就换哪个 fallback case"。
2. **Token panel 的展示条件未确认**——站长今天看到的可能是 Notion AI Agents 测试版独占功能，普通 Notion AI 用户**未必能看到**。报告把它当成"独家发现"，但对未开测试版的用户来说可能是**虚假承诺**。下次应该开两个账号交叉验证。
