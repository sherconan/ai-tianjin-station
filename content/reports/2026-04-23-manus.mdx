## 一、飞检通告

> 站长按：本档案为天津站 2026 年 4 月 23 日深夜飞检产物。受检产品：Manus。
> 站长在用户已登录的 manus.im 账号上**亲自提交一份深度调研任务**，全程不假手他人，从 prompt 投递到结果输出共 4 步、1 次中断、1 个引用错位。最终评级：**黄章 · 观察**。

一句话定位：**「会主动想、会动手、会写报告，但偶尔需要你拍它一下肩膀，提醒它别死磕」**。

Manus 把"AI 自动驾驶"做出了体感——你说一句它跑四步，每一步都把"我在干什么、我发现什么、我下一步打算干什么"摆给你看。但飞检也暴露了三件事：浏览器代理一断就要人工救援，输出引用偶有归属错位，Lite 档位的报告写到一半像被裁了一刀。

## 三、实战测试 · 站长亲跑

### 3.1 飞检任务设计

为什么不挑「写一份代码」「订一张机票」这种 demo-friendly 任务？因为那种任务的输出谁都看得见、好坏好分；**真正能照妖的是 deep research**——它要求模型主动规划、多源拼接、还要在最后老老实实交一份能用的中文报告。Manus 的招牌正是这个能力。

任务文案（站长本人手写，**未经任何模板化润色**）：

```text
调研 Anthropic 公司的 Claude Code 这款产品（CLI 编程工具，2025 年发布）。
输出一份 1500 字中文产品分析报告，包含：
(1) 一句话定位
(2) 核心 AI 能力（含 hooks / MCP / agent 等关键能力）
(3) 与 Cursor、Cline、Aider 的对比表
(4) 定价模式
(5) 真实用户口碑（HackerNews、Reddit、小红书各引用 1 条原文）。
要求引用至少 5 个真实来源链接。
```

**为什么这道题难：**
1. 需要主动浏览器访问多个数据源（HN / Reddit / 小红书）；
2. 需要识别"引用"≠"造假"；
3. 中文输出 + 表格 + 链接，多模态结构化能力；
4. 主题是它的同行（Claude Code 也是 AI agent），让 Manus 调研别人，站长正好可以用对 Claude Code 的熟悉度交叉验证。

### 3.2 任务投递

- 投递路径：在 manus.im/app 主输入框写入上文 prompt（225 个中文字符）
- 提交后 URL 自动跳转到 `manus.im/app/SSATYoHUzKvUp7iQOo8s48`，浏览器 title 自动改为「**Claude Code 2025 产品分析与对比报告**」（Manus 自己生成的标题——做得不错）
- 模型档位：左上显示 **Manus 1.6 Lite**（免费用户的默认档）
- 用户当前积分：**361 分**

> 站长打分：**入口设计干净，无任何打断。** 提交即开跑，不像某些产品要先选模式、选模型、选 agent 类型。

### 3.3 4 步执行实录

Manus 的工作面板是一根纵向的"行动流"，每一步用 `✓` 标记完成。今晚跑的 4 步：

#### Step 1 / 4 — 多渠道调研 Claude Code 产品信息

```
✓ 知识已调取(1)                       ← 检索内置 RAG 知识库
✓ 搜索 Claude Code 的官方介绍、核心能力、定价和发布信息
✓ 访问 Claude Code 官方文档以获取核心能力和技术细节
✓ 搜索 Claude Code 与 Cursor、Cline、Aider 的对比评价
✓ 搜索 HackerNews、Reddit 和小红书上的真实用户评价
```

**Manus 中间总结（原话）：**
> 我发现 Claude Code 主打结合推理与文件操作的 AI 能力，支持 hooks 和 MCP 机制，定位为开发辅助工具，价格调整引发关注。下一步将整理竞品对比。

> 站长打分：**这是 Manus 区别于普通 chatbot 的关键动作。** 它不是把所有搜索结果攒一堆扔给你，而是中途给一个"我读到了什么"的小结。这种"递进式可见性"本身就是产品力。

#### Step 2 / 4 — 拓展深度阅读（出事的一步）

```
✗ 访问 Reddit 讨论帖以获取详细的用户口碑
   ↓
   授权在您的浏览器中打开新标签页以继续？
   （因为您启用了 My Browser 连接器）
   [扩展设置]  [不，用默认浏览器]  [授权]
   ↓
   错误：Error: VNC disconnected
   ↓
   Manus 将在你回复后继续工作
   等待用户...
```

**这是飞检的关键一幕。**「My Browser 连接器」是 Manus 提供的本地浏览器接管能力（让 Manus 用你已登录的 Chrome 去访问需要登录的网站，例如 Reddit / 小红书）。它通过 VNC 协议连接你的桌面浏览器——但只要你的浏览器**焦点切走**或者**网络抖动一下**，VNC 就会断，整个任务就卡在"等待用户"。

**站长决策：** 选择「不，用默认浏览器」让任务继续。Manus 立刻退回到无登录态的公开搜索路径继续往下跑。

> 站长打分：**优雅但脆弱。** 这种"中断 → 等待 → 用户拍肩 → 继续"的设计，对站长这种坐在屏幕前的用户没问题；但**让它在凌晨自己跑着的用户来说，第二天醒来会发现任务卡了一晚上**。Anthropic Computer Use、OpenAI Operator 都有类似问题——这是当前 Browser-using Agent 的通病，但 Manus 的报错文案直白（"Error: VNC disconnected"）算诚实。

#### Step 3 / 4 — 整理对比与口碑

```
✓ 搜索小红书上关于 Claude Code 的具体评价原文
✓ 保存调研到的 Claude Code 关键信息
```

**Manus 中间总结（原话）：**
> 通过调研发现，Claude Code 在性能方面优于 Cursor 和 Aider，尤其在处理大规模、复杂代码时，但价格较高。目前我将整理详细对比和用户评价。

> 站长打分：**结论已经预先成型了。** 这种"经验性观察"在 deep research 里其实是有偏见的——Manus 没有调研 Cursor 的最新版本（2026 年 Cursor 已经把 Composer 升到了第三代），就敢下"性能优于 Cursor"的判断。这是 LLM 通病，不全怪 Manus。

#### Step 4 / 4 — 撰写并输出完整产品分析报告

最终输出：一份结构完整的中文报告 + 1 个 `Claude_Code_Analysis_Report.md` 附件。报告里有 6 个一级章节、1 张完整对比表、3 条用户口碑引用、5 个参考链接。

**关键产出节选**（Manus 原话，未做任何修饰）：

> 不同于传统的对话式 AI，Claude Code 具备自主规划（Planning）和执行（Execution）的能力。当用户输入一个高层指令（如"重构整个认证模块以支持 OAuth2"）时，它会先扫描项目结构，制定多步执行计划，并逐一执行文件读写、命令运行和结果验证。

> Hooks（钩子机制）：支持在任务执行的生命周期中插入确定性脚本。例如，通过 pre-run 钩子在修改前自动备份，或通过 post-run 钩子在修改后强制运行 npm test 或 eslint。

> Subagents（子智能体）：这是处理大规模代码库的杀手锏。Claude Code 可以派生出多个子智能体，在隔离的上下文中并行执行任务（如在数千个文件中搜索特定模式），最后仅将总结结果返回主进程。

**对比表片段**（Manus 自己做的）：

| 维度 | Claude Code | Cursor | Cline | Aider |
|---|---|---|---|---|
| 产品形态 | CLI（命令行原生） | IDE（VS Code 分叉） | VS Code 插件 | CLI（命令行） |
| 交互哲学 | 自动驾驶智能体 | 增强型副驾驶 | 插件化智能体 | 精准协作工具 |
| 上下文管理 | 贪婪模式 | 索引模式（RAG + @） | 手动模式 | 精确模式 |
| 上手门槛 | 中（命令行） | 低（开箱即用） | 中 | 中 |

### 3.4 站长亲查 · 引用真伪审核

这是飞检最严的一关——**Manus 给了 5 个引用链接，站长逐一核查**：

| 来源 | Manus 给的链接 | 站长核查结论 |
|---|---|---|
| Anthropic 官网 | `code.claude.com/docs` | ✅ 真实存在，路径合理 |
| Anthropic 价格页 | （Pro $20/月） | ✅ 价格属实，但 2026 年已有 Max $200 档，未提 |
| HackerNews | `news.ycombinator.com/item?id=47866913` | ⚠️ ID 形式合理，未链上验证 |
| Reddit | `reddit.com/r/ClaudeAI/comments/1jku9d2/claude_code_vs_cursor_windsurf_and_cline_worth_it/` | ⚠️ URL 结构合理，未链上验证 |
| 「小红书」 | `zhuanlan.zhihu.com/p/1998820316168860488` | ❌ **这是知乎链接，不是小红书** |

**最关键的一处错位：** Manus 在第 5 条引用里把「小红书」标签贴到了知乎（`zhuanlan.zhihu.com`）的链接上。原文如下：

> 5.3 小红书（效率与门槛的突破）
>
> "小白选工具逻辑很简单：选公认智商最高、质量最稳的。Claude Code 宣称能独立跑七个小时，发力做'长期任务执行'。虽然收费贵，但充值 150 人民币能做好几个项目的需求文档..."
>
> [5] 小红书/知乎：AI 编程工具实战心得 (2026) — `zhuanlan.zhihu.com/p/1998820316168860488`

注意 Manus 自己在引用里写的是「**小红书/知乎**」，技术上诚实标了双标签——但**正文却把它单独归类为"小红书"**。这是飞检发现的最实锤的一处归属错位：模型在小红书的真实数据里找不到对应原文，于是用一篇知乎长文凑数，并把"小红书 ✓"打了勾。

> 站长打分：**态度比能力诚实。** 它没有伪造一个不存在的小红书 URL（这一步至少守住了底线），但归因仓促。**深度研究产品的命门是引用可信度**——这一处必须扣分。

## 四、核心 AI 能力拆解

通过这一晚的实测，站长把 Manus 1.6 Lite 的能力拆成 5 层：

### 4.1 Plan-First 拆解能力 ⭐⭐⭐⭐

输入一个 200 字 prompt，Manus 立刻回："我先制定一个调研和写作计划"，然后产出一个**多步骤待办**。这件事很多产品都做，但 Manus 的细节是 **任务名会自动生成**（"Claude Code 2025 产品分析与对比报告"），而不是用 prompt 第一句当 title。

### 4.2 多源调研 + 中间结论 ⭐⭐⭐⭐

每一组搜索之后必有一条"我发现……下一步……"的中段总结。这不是噱头，**它对失败回滚有用**：当某个搜索失败（如 VNC 断开），用户能凭中段总结判断是否值得继续。

### 4.3 工具协同（Browser + RAG + 文件） ⭐⭐⭐

Manus 的工具栈：
- 内置知识库（"知识已调取(1)"）
- 公开 web 搜索
- 浏览器接管（My Browser 连接器，VNC 协议）
- 文件输出（自动产出 .md 附件）

**短板：** Browser 接管太脆弱。VNC 断了之后没有自动重连，只会等用户。

### 4.4 进度可视化 ⭐⭐⭐⭐⭐

最强的一项。Manus 的"4/4"任务进度条 + 每步可展开看子动作 + 每步独立 ✓ 状态——**这就是「show your work」做对了的样子**。OpenAI Operator 的"Working..."黑盒就是反面教材。

### 4.5 中文输出与结构化 ⭐⭐⭐

中文报告流畅，对比表用 Markdown 表格，引用编号 [1][2][3]。但**到第 6 章被截断**（"Claude Code 不仅仅是一个编程助手，它是 Anthropic 对'未来开发范式'的尝试：**开发者..."** 这里直接断了）。这是 Lite 档的字数限制造成的。

## 七、站长锐评

### 让站长想盖绿章的：
1. **进度可视化做到了行业标杆。** 4 步进度 + 中段总结 + 可展开子动作，这套交互是教科书级别。
2. **任务标题自动生成。** 这种"省力但讨好"的细节是产品力。
3. **诚实标注「小红书/知乎」双标签**（虽然正文归错了），底线没破。
4. **VNC 断了不假装没事**，明确报错并请求用户决策。

### 让站长摇头的：
1. **VNC 中断毁掉无人值守体验。** 一旦设置了 My Browser 连接器，用户必须坐在屏幕前。
2. **引用归属错位。** 把知乎链接打上"小红书"标签，是 deep research 产品的硬伤。
3. **Lite 档报告被截断。** 不告诉你"我被压缩了"，只是让最后一段消失。
4. **预先成型的结论。** "Claude Code 性能优于 Cursor"——这种武断结论应该在 deep research 里被证据驱动，而不是模型自己脑补。

### 站长想问蝴蝶效应团队的三个问题：
1. VNC 断连后能不能自动 fallback 到无登录搜索，并在最终报告里标注"该来源未访问"？
2. 引用归属能不能加一道事后校验：URL host ≠ 标签 source 时，强制改写为正确归属？
3. Lite 档输出被截断时，能不能至少在 UI 上加一个"完整版需 Pro"的提示？

## 八、飞检结论

### 评级：**🟡 黄章 · 观察**

| 项 | 评分 | 说明 |
|---|---|---|
| 任务理解 | A | prompt 一次性吃透，无需追问 |
| 拆解规划 | A | 4 步合理 |
| 工具调用 | B+ | VNC 中断扣分 |
| 输出质量 | B | 引用归属错位扣分 |
| 中文表达 | A | 流畅，结构化做得好 |
| 进度透明 | A+ | 行业标杆 |
| 容错恢复 | C | VNC 断了只能等用户 |

**综合：** Manus 已经过了"是不是玩具"的关，但还没过"能不能让站长无人值守"的关。所以**先发黄章，留观下次飞检**——下次切到 Pro 档跑一次复杂编程或多文件输出任务，再决定是否升绿。

### 给我们（产品人）的启示：

1. **「进度可视化」是 Agent 类产品的护城河。** Manus 之所以让人愿意看完 4 步过程，是因为每步都给了"我读到什么"的小总结。把这个动作搬到任何 Agent 产品里都能立刻拉开差距。

2. **「任务标题自动生成」是省力的高 ROI 细节。** 别让用户自己给对话起名字。

3. **「Browser 接管」是 2026 年最难做的能力之一。** 即使 Manus 这样的头部产品，VNC 接管的稳定性仍是最大短板。如果你做 Agent 产品，**先想清楚是用云端虚拟机（贵但稳）还是用户本机接管（便宜但脆）**。

4. **「免费档报告截断」是反面教材。** 如果一定要限制免费档的输出长度，就在 UI 上明示，而不是让用户读到一半发现断了。

5. **「引用归属」是 deep research 产品的命门。** 一处错位就足以让企业用户失去信任。
